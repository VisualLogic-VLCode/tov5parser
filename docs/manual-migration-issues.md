# V4 → V5 自动转换无法解决的问题

本文记录 V4 案例能够完整转换为 V5 JSON，但由于 V4/V5 底层运行架构或动作执行语义不同，转换结果仍无法直接工作的情况。

这类问题不属于节点、属性、公式或动作 AST 丢失。转换器无法仅根据 JSON 安全推断原业务对并行、等待、回调时机和 UI 更新时机的真实依赖，需要在 V4 案例中调整业务逻辑后重新转换。

## 收录标准

同时满足以下条件的问题应记录在本文：

1. V4 节点、属性、绑定、事件和动作均已完整转换。
2. V5 AST 引用的节点、参数和作用域正确。
3. 故障由 V4/V5 运行架构或执行顺序差异引起。
4. 转换器无法在不影响其他案例语义的前提下自动决定正确行为。
5. 需要开发者在 V4 中显式重构业务时序、并行关系或状态更新方式。

---

## 1. 回调动作在 V4 中并行发起，转到 V5 后按顺序阻塞

### 案例

- 案例：`frp-pad`
- 现象：V5 预览中“量体部门”列内容变高后，表格行高没有随内容自动增加。
- V4 预览：`https://giupre.h5app.com/play/wt5RnwSK@10000590`
- V5 预览：`https://giupre.h5app.com/play/cFk6XuDE`

### V4 的实际执行语义

`crn0n2wa3j50000ag9tg` 中的四个详细信息动作都有回调能力，但其 `status` 分支只是空占位，没有承接返回值或后续业务动作。

V4 运行时发起这四个异步动作后，不等待其完成，立即继续外层动作。因此执行顺序为：

1. 设置量体列表。
2. 并行发起用户、部门、公司和角色等详细信息请求。
3. 立即调用 `crqfse5a3j50000a6en0`，为每行建立默认高度 52 的记录。
4. 文本初始化或值变化后读取 `_boundHeight()`。
5. `cvrgkvfa3j50000vq3tg` 在已经存在的行高记录上更新实际高度。

### 转成 V5 后的实际执行语义

V5 使用 `async/await` 顺序执行动作。上述四个动作因为方法具备 callback 能力，被转换为 `op:"let"`，并依次等待完成。

执行顺序变为：

1. 设置量体列表，文本组件开始渲染。
2. 依次等待四个详细信息动作完成。
3. 文本的 0.1 秒初始化延时先结束，读取到实际高度并调用行高更新。
4. 此时 `ctmch3ca3j50000k5p6g` 仍是空数组，`arrUpdate` 匹配不到数据。
5. 四个详细信息动作全部完成后，才调用行高处理并写入默认高度 52。
6. 文本值没有再次变化，之前失败的测高更新不会重新执行，最终行高停在 52。

运行日志已经验证：

- V5：文本 `_boundHeight()` 正常返回 49，但执行行高更新时行高列表为 `[]`；随后才输出“进入行高处理”并创建四条记录。
- V4：先输出“进入行高处理”并创建四条记录，随后文本测高和行高更新才执行。

### 为什么转换器不能通用修复

转换器只能看到动作支持 callback、存在空 `status` 占位以及动作排列顺序，无法确定业务真正需要哪一种语义：

- 四个请求是否应该完全并行；
- 外层动作是否应该等待其中一个或全部请求；
- 后续动作是否依赖请求返回的数据；
- 空 `status` 是有意表示“不等待”，还是案例编辑过程遗留的空结构；
- V5 中取消等待是否会让其他案例读取到尚未返回的数据。

如果转换器统一取消 `await`，会破坏真正依赖前序返回值的案例；如果统一保留 `await`，又会改变依赖 V4 非阻塞行为的案例。因此不能仅凭结构做安全、通用的自动修复。

### V4 业务逻辑改造建议

优先在 V4 中把依赖关系写明确，再重新转换：

1. 在设置量体列表后，立即调用 `crqfse5a3j50000a6en0` 初始化行高列表。
2. 行高列表初始化完成后，再发起 `crn0n2wa3j50000ag9tg` 中的详细信息请求。
3. 如果详细信息会改变文本内容，应在所有相关数据更新完成后，显式再次触发行高测量。
4. 不要依赖“异步动作虽然排列在前面，但 V4 不等待它完成”这种隐式时序。
5. 需要并行的请求应通过业务动作组明确表达并行；需要等待的结果应通过有效的完成回调明确串联。

本案例最小改造是把行高列表初始化提前到详细信息请求之前，使 V4/V5 中的文本测高更新都能找到对应行记录。

### 验收条件

重新转换后应满足：

1. 文本测高动作执行前，`ctmch3ca3j50000k5p6g` 已包含当前列表的全部数据 ID。
2. 内容高度超过 52 时，行高记录能更新为实际测量值。
3. 同一行的所有单元格使用相同更新后高度。
4. V4 与 V5 的关键执行顺序一致，不再依赖回调架构的隐式非阻塞行为。
